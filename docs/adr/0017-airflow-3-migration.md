# ADR 0017 — Airflow 3: four components, Execution API, deadlines instead of SLAs

**Status:** accepted (Airflow 3.3.2, Python 3.12, LocalExecutor, astronomer-cosmos 1.15.1).

**Context.** The lab ran Airflow 2.9.0. The 2.x line reached end of life on 2026-04-22 (no security fixes), and
the portfolio is meant to show a current stack. Loaded by Airflow 3.3.2 unchanged, 5 of the 8 DAGs did not even
import (`airflow.datasets` is gone), the other 3 ran on deprecated paths, and `ruff --select AIR3` reported 46
findings. The lint is necessary but not sufficient: three of the breaking changes below only show at run time,
and two of them fail *silently*.

**Decisions.**

1. **Four processes instead of two** (`docker-compose.yml`). `api-server` (React UI + REST API v2 + Execution
   API) replaces `webserver`; DAG parsing leaves the scheduler for a `dag-processor`; a `triggerer` runs deferred
   work. The scheduler waits for the API server to be healthy: with LocalExecutor it runs tasks, and every task
   talks to the Execution API (`AIRFLOW__CORE__EXECUTION_API_SERVER_URL`).
2. **Shared secrets are mandatory, enforced by compose.** Task tokens are JWTs; if each container makes its own
   key, every task fails with 403. `AIRFLOW__API_AUTH__JWT_SECRET` and `AIRFLOW__API__SECRET_KEY` (replaces
   `AIRFLOW__WEBSERVER__SECRET_KEY`) live in `.env`, generated by `make env` (also into an existing `.env`), and
   compose refuses to start without them (`${VAR:?missing in .env, run make env}`).
3. **Same login model.** `FabAuthManager`, so the admin from `.env` is created by `airflow-init` as before (the
   Airflow 3 default, SimpleAuthManager, would generate passwords into a file).
4. **Imports from the Task SDK and the standard provider.** `airflow.sdk` (`DAG`, `Asset`, `Param`, `TriggerRule`)
   and `airflow.providers.standard` (Bash/Python/Empty/ShortCircuit/TriggerDagRun operators, FileSensor).
   `Dataset` → `Asset`, same URIs, so the producer → consumer wiring is unchanged.
5. **SLAs → DeadlineAlert** (`dag_helpers.run_deadline`). Airflow 3 accepts `sla=` and `sla_miss_callback` and
   ignores them: the ANP 3 h SLA would have stopped alerting with no error. The DAG now declares a deadline of
   3 h from the moment the run is queued; on a miss the executor runs `on_deadline_missed` (`SyncCallback`, no
   triggerer round trip), which logs the same `sla_missed` event and sends the alert through the same channel.
6. **No metadata DB in task code.** Tasks only reach the Execution API. The audit gate (`audit_logger`) used
   `dag_run.get_task_instances()` inside a `try/except` returning `[]`: on Airflow 3 that would turn every failed
   run green. It now reads `ti.get_task_states()` and, on purpose, has no `except`: if the states cannot be read,
   the task fails.
7. **Runs without a logical date.** Manual, asset-triggered and TriggerDagRunOperator runs have
   `logical_date = None`, and the keys `logical_date`/`ds`/`ts`/`ts_nodash` are *absent* from the template context:
   `{{ ts_nodash }}` and even `{{ logical_date or ... }}` fail with `'logical_date' is undefined`. One constant,
   `RUN_TS = {{ (dag_run.logical_date or dag_run.run_after) | ts_nodash }}`, names the NF-e batches and the
   Elementary reports for every run type; the audit file falls back to `run_after`.
8. **Logs are JSON lines.** Every task log line is now `{"timestamp", "level", "logger", "event", ...}`. Promtail
   unpacks that envelope before our own `LEVEL logger: msg | {json}` parser, upper-cases the level (Airflow writes
   `info`/`error`; dashboards query `ERROR|WARNING`), keeps the task's timestamp and stores the readable body.
   Two new log sources are shipped: `logs/dag_processor/` (was `logs/scheduler/`) and `logs/executor_callbacks/`,
   where deadline callbacks write. The human audit trail renders the JSON back to `[ts] LEVEL logger - msg`.
9. **AI layer: sentence-transformers 5/6.** The Dockerfile freezes every base package as a constraint for the
   `INSTALL_AI` layer. The Airflow 3.3.2 image ships `tokenizers` 0.23.2, while all of transformers 4.x needs
   `tokenizers<=0.23.0`; `sentence-transformers<5` pins transformers 4, so the build was impossible (pip blamed
   numpy while backtracking). `sentence-transformers>=5,<7` → transformers 5 (torch ≥ 2.6; the image has 2.8.0).
   The call sites (`SentenceTransformer(name)`, `encode(..., normalize_embeddings=True)`) are unchanged in the
   6.x API. The CI job dry-runs the AI layer against the Airflow constraints.
   Embeddings already stored in pgvector were made by transformers 4: same weights and tokenizer, so the
   vectors are expected to match within float error; checked by comparing both images before reusing them,
   otherwise re-embed (lc04 / rag01).
10. **Metrics.** Every StatsD family the dashboards use is still emitted. Only
   `dag_processing.last_duration` gained the bundle name (`.dags-folder.`); the mapping turns it into a `bundle`
   label so `dag_file` keeps the bare file name.
11. **In-place upgrade, no volume to drop.** `airflow-init` runs `db migrate`, which takes an Airflow 2.9 metadata
    DB to 3.3.2 in place, run history included. The Grafana queries on the metadata DB (`dag_run`,
    `task_instance`) need no change.
12. **Guardrails in CI.** `AIR3` is part of `ruff check .`; `tests/test_airflow3_guardrails.py` (no Airflow)
    rejects logical-date keys in templates and metadata-DB access in task code; the `airflow-dags` job installs
    Airflow 3.3.2 with the official constraints and parses the DAGs with the dag-processor's DagBag (import
    errors, deprecated APIs, callbacks on every task, the ANP deadline, the asset wiring, `RUN_TS` rendered with
    and without a logical date).

**How it was validated.** Airflow 3.3.2 from the official constraints, the four components against Postgres 16,
the repo's own bootstrap and dbt project, MinIO replaced by an S3 emulator:

| Check | Result |
|---|---|
| Airflow 2.9 metadata DB with history → `airflow db migrate` | migrated in ~6 s, `dag_run`/`task_instance` kept |
| Grafana panels on the metadata DB (`tests/test_dashboards_sql.py`) | 6/6 pass on the migrated schema |
| DagBag | 8/8 DAGs, 0 import errors, 0 deprecation warnings |
| `dag_nfe`, scheduled run | sensor → batch → SQL bronze → 36 Cosmos tasks → finalize: batch `PROCESSADO`, 307/308 loaded, the corrupt XML rejected |
| `dag_nfe`, manual run (`logical_date = None`) | failed on `{{ logical_date or ... }}` (finding 7), then green with `RUN_TS`: batch named from `run_after` |
| `dag_setup_infrastructure` via trigger | green; audit summary from the Execution API; audit log uploaded to S3 |
| Probe run with one failing task | gate failed the leaf (`... failed task(s): boom`), run red; failure callback + alert; the gate's own failure not re-alerted |
| DeadlineAlert of 20 s on a 60 s run | missed 1 s after the deadline; `sla_missed` + alert from the executor |
| Promtail 2.9.2 → Loki 2.9.2 on the real logs | `level` ERROR/WARNING, `event`, `dag_id`, `task_id` labels; `task_failed`, `alert`, `sla_missed` all queryable |
| Asset event on `datalabs://landing/rfb` | `dag_rfb_dw_dbt` triggered; Elementary report path rendered from `run_after` |

**Consequences.**

* More memory: idle RSS measured in the validation was ~350 MB api-server, ~310 MB scheduler, ~220 MB
  dag-processor and ~300 MB triggerer (~1.2 GB for Airflow). The triggerer is unused by today's DAGs; it is kept
  for the standard topology (deferrable sensors and async callbacks work without touching compose). On a tight
  laptop, removing it is one block in `docker-compose.yml` and one line in `scripts/doctor.sh`.
* The UI is the new React app (light/dark toggle); links are `/dags/<dag_id>` (there is no `/grid` route).
* `soft_fail` on the NF-e sensor now skips only on timeout; a real error in the poke (e.g. a missing
  connection) fails the task instead of hiding as a skip, which is what the old comment warned about.
* An Airflow 2 `.env` keeps an unused `AIRFLOW__WEBSERVER__SECRET_KEY` line: harmless, can be deleted.
* Upgrades inside 3.x: bump the `FROM` tag, `AIRFLOW_VERSION` (Dockerfile) and the `airflow-dags` CI job
  together; the CI job proves the constraints resolve before the image is built.
